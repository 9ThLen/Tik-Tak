# ADR 0001 — Ядро аналізу на портативному C++ за плоским C API

**Статус:** прийнято
**Дата:** 2026-07-25

## Контекст

Застосунок виходить спершу на iOS, Android заплановано. Уся цінність проєкту —
в аналізі аудіо: STFT, onset detection, оцінка темпу, трекінг долі, детекція
сильної долі. Це кілька тисяч рядків нетривіальної математики.

Природний шлях для iOS-first — писати DSP на Swift поверх `vDSP`/`Accelerate`
і `CoreML`. Але тоді поява Android означає повний перепис цієї математики
на C++/Kotlin, з нуля і з нуля ж перевірений.

## Рішення

Уся математика — один портативний **C++17** без залежностей від платформи,
у `core/`. Платформи звертаються до нього через **плоский C API**.

Apple-специфічні бібліотеки замінено на портативні:

| Було | Стало |
|---|---|
| `vDSP` FFT | власний radix-2 за абстрактним інтерфейсом, далі PFFFT |
| `CoreML` | ONNX Runtime Mobile (CoreML EP на iOS, NNAPI на Android) |
| `AVAudioFile` | `dr_libs` для mp3/wav/flac; m4a лишається платформенним |

Платформенними лишаються лише тонкі оболонки: захоплення й відтворення звуку
(AVAudioEngine / Oboe), вібрація, вибір файлу, UI.

### Чому саме плоский C, а не C++ ABI

- Swift викликає C напряму через module map — Objective-C++ прошарок не потрібен.
- JNI природно працює з C-сигнатурами.
- Стабільний ABI: ядро можна оновлювати незалежно від оболонок.

## Наслідки

**Добре:**
- Android отримує вже перевірене ядро — лишається робота з платформою, не з алгоритмами.
- Ядро збирається й тестується на Linux нативно (CMake + googletest), тобто основну
  частину проєкту можна розробляти поза Xcode і покривати тестами по-справжньому.
- Абстрактний інтерфейс FFT лишає можливість підставити `vDSP` на iOS, якщо
  профілювання покаже відчутну різницю.

**Погано:**
- Вища складність на старті: CMake, крос-компіляція, дві збірки в CI, C-межа
  замість природних Swift-типів.
- Втрачаємо ручну оптимізацію Apple під конкретне залізо. Пом'якшується тим, що
  PFFFT на NEON близький до vDSP, а мережа однаково йде на Neural Engine через
  CoreML execution provider.

**Обов'язково:** CI збирає ядро під iOS і Android **від першого дня**, ще до появи
Android-застосунку. Інакше ядро непомітно обросте Apple-залежностями.
