# ADR 0002 — Нативний UI на кожній платформі (SwiftUI, згодом Compose)

**Статус:** прийнято
**Дата:** 2026-07-25

## Контекст

Після ADR 0001 ядро аналізу — портативний C++. Питання, що лишилось: чи має UI
теж бути спільним (Flutter / React Native / Kotlin Multiplatform), чи нативним
на кожній платформі.

Раніше головний аргумент проти крос-платформних фреймворків був «аудіо-рушій
усе одно доведеться писати нативно, тож виграш уявний». Після винесення ядра
в C++ цей аргумент відпав: Flutter звертався б до того самого ядра через FFI
не гірше за Swift.

## Рішення

**Нативний UI: SwiftUI на iOS, Jetpack Compose на Android.**

iOS — головна платформа, тож починаємо зі SwiftUI; Compose з'являється у Фазі 9
разом з Android-застосунком.

### Чому

1. **Поверхня UI дуже мала.** Пульсуючий індикатор долі, регулятор BPM, вибір
   розміру такту, кілька перемикачів каналів підказки, екран імпорту файлу,
   екран калібрування. Дублювати таку поверхню дешевше, ніж вносити в проєкт
   цілий додатковий тулчейн.
2. **Кадрово точна анімація долі — критична.** Візуальний пульс мусить збігатися
   з аудіо-кліком і вібрацією з точністю до кадру, а всі три канали планує
   спільний годинник у C++. Кожен додатковий шар рендерингу між цим годинником
   і склом — це ще одне джерело затримки й джитера саме там, де вони найбільше
   помітні.
3. **Прямий доступ до платформенного API.** CoreHaptics і `CADisplayLink`
   (відповідно `VibrationEffect` і `Choreographer`) використовуються глибоко
   і з точним таймінгом — через міст це завжди гірше.

## Наслідки

**Добре:** найкраща якість відчуттів там, де вона найбільше важить; жодних
обмежень платформи; менше залежностей.

**Погано:** UI пишеться двічі. Приймаємо свідомо — при цьому обсязі екранів
це тижні, а не місяці, і воно не стосується алгоритмічної частини.

**Ризик:** якщо UI несподівано розростеться (соціальні функції, редактор
партитур, велика бібліотека треків), баланс може змінитися. Тоді ADR варто
переглянути — але переписувати доведеться лише оболонку, бо вся логіка
й так у ядрі.
